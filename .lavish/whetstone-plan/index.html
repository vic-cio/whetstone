A. Three design directions

Each candidate is shown as the two screens you will use most: the Dashboard and a Lesson with a Task and its Verdict. The layout, tokens, and type differ. The information on screen is identical, so the differences are purely the design. All three use a fixed five-step tint for Depth and an icon for Check: ⚡ grades instantly offline, ✦ needs a model and costs money.

How a Course gets built, for any Harness

B3. Course format

One folder is the whole Course. It holds no progress and no Tutor chat, so copying it shares the Course and trashing it deletes the Course.

courses/<slug>/
  course.json          manifest, objectives, ladder, modules, suggestedOrder
  lessons/<id>.md      prose plus :::block directives
  tasks/<id>.json      one Task: objective, depth, check, kind
  apps/<id>/index.html one self-contained Mini-app
  resources.json       links with one line of why

A Lesson is made only of six Blocks: prose, callout, diagram, task, app, resource. No raw HTML, no script.

Depth and Check are independent. Every cell below is legal. Check alone decides offline, cost, and the marker.

Deterministic kinds, all graded by the host

kindAnswer shapeCompared how
multiple-choiceOne or more option indexesSet equality
numericA numberWithin tolerance
exact-textA short stringTrimmed, case-folded, whitespace-collapsed
orderingA permutationSequence equality
app-resultWhatever the Mini-app postsDeep equality with answer. The Mini-app never grades itself

B4. Sandbox boundary

Written before the first Mini-app runs. Test 7 proves each line in a real browser.

A Mini-app cannot
  • Read or write any file.
  • Open any network connection. connect-src 'none', and Electron blocks every request from the sandbox origin.
  • Load an external script, style, font, or image. Inline and data: only.
  • Read the Progress DB, the Course folder, or host state.
  • Navigate the host, open windows, or show dialogs.
  • Share an origin with the host. No allow-same-origin, so no storage either.
A Mini-app can
  • Run script, draw, animate, take input.
  • Receive one init message with { taskId?, inputs }.
  • Send ready, resize { height }, and result { payload }.
  • Fail on its own. A crash shows a plain card with reload and a defect report link. The Lesson stays up.

B5. Phases and tests

Each phase ends with a runnable app. Tests are written before the phase they belong to.

  1. Skeleton and formatElectron, React, Tailwind, shadcn, SQLite. Format schema, parser, validator, fixture Course. Tests 1, 2, 3.
  2. Study offlineSidebar, Course page, Lesson reader, every deterministic kind, Attempts, known-already, Dashboard. Tests 6, 9. Usable with hand-written Courses.
  3. Mini-appsSandbox host, message protocol, app block, app-result kind. Test 7.
  4. ConstructorHarness contract, Claude Agent SDK adapter, prompt files, staging and validation, RunView with live log and spend meter, Keychain, new-course form, Delete Course. Tests 5, 8, 11. API key wizard.
  5. Tutor and GraderProvider contract, Anthropic adapter, model and rubric checks, Submissions through the Files API, Verdict view, defect reports, Tutor panel with caching. Tests 4, 10.
  6. Non-linear studyReview sessions, miss queue, add-rung and remediate runs, remediation offer after repeated fails.
  7. More harnesses and providersCodex adapter, pi adapter, OpenAI Provider. Each verified from its docs at this point.
  8. FinishDark mode, keyboard navigation, spend dashboard, export a Course as a zip, icon and signed build.
